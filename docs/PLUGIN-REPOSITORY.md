# Combo and Oracle plugin repository

The `plugin-repo` branch hosts the combined Dalamud feed and plugin ZIPs.

Add this URL in `/xlsettings` → **Experimental** → **Custom Plugin Repositories**, enable it, and save:

```text
https://raw.githubusercontent.com/WayneXXDD/Combo/plugin-repo/pluginmaster.json
```

Then use `/xlplugins` to install **XIV Combo Expandedest (Wayne)** or **Oracle (Wayne)**.
The original internal names are retained so their existing configuration files remain compatible.

## Publishing updates

**Build and publish plugin repository** builds Combo from the triggering commit and Oracle from the current `main` branch.
It runs Combo's offline checks, builds both plugins, derives numeric versions from the DLLs, validates the package layouts,
includes the original licenses, and writes the complete feed only after both builds succeed.
The publication job can write only the `plugin-repo` distribution branch and rejects version downgrades.
It does not push to the original authors' repositories and requires no additional personal access token.

Pushes to Combo's `master` branch trigger publication. After updating Oracle, run this workflow manually
from Combo → **Actions** → **Build and publish plugin repository** → **Run workflow**.
Publishing both repositories through this one workflow keeps the combined feed consistent without granting cross-repository write credentials.

Dalamud decides whether an update is available by comparing **AssemblyVersion**, not the ZIP date or product-version label.
Increase the numeric assembly version when releasing changed plugin code.
Combo currently uses `1.5.0.96`. Oracle's product version is `1.2.3_own`, while its assembly version is `1.2.3.0`.
When updating Oracle, increase its `AssemblyVersion` and `FileVersion` in `Oracle.csproj` as well as the product/package version.
The packaging script updates its generated JSON to match the compiled DLL automatically.

Do not edit `plugin-repo` manually: it is generated by the workflow. Change source projects, packaging scripts,
or this workflow in the source repositories instead. A `DalamudPluginRepository` artifact is also kept for 14 days;
the files served from `plugin-repo` have no Actions artifact expiration.
